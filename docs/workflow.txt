Sì. Ti faccio un esempio **debug-level**, cioè non quello che vede l’utente finale, ma quello che succede internamente oggi nel runtime.

Userò un task adatto al gateway MCP attuale:

```text
Task utente:
"Analizza questo testo e dimmi quali parole ricorrono di più: 'agent agent governance MCP evidence evidence evidence'."
```

Nel runtime attuale, un caso del genere può usare il tool MCP:

```text
mcp.local_test.text_stats
```

che passa da:

```text
actor -> ToolRequest -> governance -> tool_gateway -> MCP server -> ToolExecutionResult -> ObservedEvidence -> actor
```

## 1. Ingresso Utente

L’utente invia testo libero:

```json
{
  "raw_task_text": "Analizza questo testo e dimmi quali parole ricorrono di più: 'agent agent governance MCP evidence evidence evidence'.",
  "context_hint": "Usa strumenti read-only se utili."
}
```

Questo entra in:

```text

```

che prima passa da Layer 1.

L’actor decide che serve un tool read-only.

Non chiama MCP direttamente.

Produce un `ActorResult` di tipo `PROPOSE_ACTION`:

```json
    "plan_step_id": "step_1",
```

Il `TaskState` ora contiene:

## 7. Tool Gateway

Il nodo `tool_gateway` riceve:

```json
{
  "tool_name": "mcp.local_test.text_stats",
  "reason": "The current step requires deterministic word frequency statistics.",
  "text": "agent agent governance MCP evidence evidence evidence",
  "limit": 5
}
```

Il gateway guarda la configurazione:

```json
{
  "tool_name": "mcp.local_test.text_stats",
  "backend": "mcp",
  "capability": "read",
  "risk_level": "low",
  "enabled": true,
  "requires_human_review": false,
  "required_fields": ["text"],
  "mcp_server_id": "local_test",
  "mcp_tool_name": "text_stats"
}
```

Poi controlla il server MCP configurato:

```json
{
  "local_test": {
    "enabled": true,
    "command": "{python}",
    "args": ["{repo_root}\\tests\\fixtures\\mcp_local_test_server.py"],
    "allowed_tools": [
      "echo",
      "read_fixture",
      "text_stats",
      "calculate_expression"
    ]
  }
}
```

Validazioni eseguite:

```text
tool registrato? sì
tool abilitato? sì
backend MCP? sì
server MCP registrato? sì
server MCP abilitato? sì
mcp_tool_name allowlisted? sì
capability read? sì
required field text presente? sì
```

A questo punto costruisce gli argomenti MCP:

```json
{
  "text": "agent agent governance MCP evidence evidence evidence",
  "limit": 5
}
```

```json
  "method": "tools/call",
  "params": {
    "name": "text_stats",
    "arguments": {
      "text": "agent agent governance MCP evidence evidence evidence",

  }
}
```

Il server MCP risponde:

## In Sintesi

Oggi il sistema fa questo:

```text
1. Utente invia task libero
2. Layer 1 lo trasforma in IntakeResult
3. Layer 2 crea TaskState
4. Planner crea piano semantico
5. Actor esegue solo il current step
6. Actor propone ToolRequest
7. Governance valuta se la tool call è ammessa
8. Tool Gateway valida registry/config
9. Tool Gateway chiama MCP
10. MCP restituisce risultato
11. Gateway normalizza in ToolExecutionResult
12. observe_tool_result crea ObservedEvidence
13. Actor usa evidenza per completare step
14. Governance rivaluta
15. Actor produce final output
16. Governance approva
17. Runtime termina in completed
```

Quindi la forma corretta da raccontare nella tesi è:

```text
L’agente appare autonomo verso l’utente, ma internamente ogni uso di capacità esterne passa da un confine governato, tipizzato e osservabile.
```
