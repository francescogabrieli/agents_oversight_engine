Current Implementation

Layer 2 Bootstrap Handoff

The active Layer 2 implementation has been intentionally reduced to the bootstrap contract between Task Intake and the first canonical TaskState. The graph no longer contains planner, governance, HITL, or tool execution nodes. Its only purpose is to receive IntakeResult, build TaskState, and stop after the bootstrap handoff.

Executable Graph

This figure reflects the current code in src/layer2_runtime_governance/graph.py. The executable path is minimal by design so the repository can stabilize the Layer 1 to Layer 2 handoff before reintroducing agentic runtime nodes.

What Bootstrap Does

  • copies the full IntakeResult into TaskState.intake_payload
  • extracts task_spec, execution_policy, and intake_metadata
  • maps parse_status into the initial current_state
  • sets runtime flags such as clarification, incomplete intake, read-only mode, and high sensitivity
  • records the first audit entry in step_history

Bootstrap Mapping Rules

The rules below summarize the current deterministic handoff implemented by TaskState.from_intake(...) and bootstrap_from_intake(...).

Layer 1 Source Layer 2 Target Rule
structured_task.task_spec TaskState.task_spec Copied directly.
structured_task.execution_policy TaskState.execution_policy Copied directly.
metadata TaskState.intake_metadata Copied directly.
IntakeResult TaskState.intake_payload Preserved in full for auditability.
parse_status = complete current_state = planning Normal executable intake.
parse_status = partial current_state = planning + incomplete_intake Bootstrap preserves the need for downstream caution.
parse_status = needs_clarification current_state = waiting_human_review + clarification_required Bootstrap marks the task as not directly executable.
execution_policy.read_only_mode = true read_only_execution Captured as runtime flag.
sensitivity in {high, critical} high_sensitivity Captured as runtime hint immediately at bootstrap.
